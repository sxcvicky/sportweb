# 知识库结构

> 目标：初期覆盖尽量广，单点深度可以浅。先保证每个档位、每个行业都有一张可检索的事实卡，再逐步加深。
>
> 报告侧只保留 20–30 张“诊断模式卡”和少量市场规则卡，不建 SKU 商品库。SKU 的差异由用户填写的售价、成本、广告和退货数据带入，避免知识库变成数据库。

## 一、三层结构

```text
通用层：市场、平台、合规、成本、物流、支付、风险
行业层：品类事实卡（3C、家居、服饰、美妆、宠物、户外等）
阶段层：4 个档位的判据、常见瓶颈、动作库、基准
```

## 二、通用层

| 模块 | 至少覆盖 | 例子 |
|---|---|---|
| 市场 | 美国、欧洲、东南亚、日本、中东、巴西、智利、拉美 | 市场准入、消费习惯、季节、关税 |
| 平台 | Amazon、TikTok Shop、Temu、Ozon、Mercado Libre、独立站 | 入驻、佣金、流量、广告、退货规则 |
| 合规 | 主体、VAT、EPR、GPSR、认证、标签、HTS | 什么品类要什么、什么时候做、不做会怎样 |
| 成本 | 货值、头程、尾程、佣金、广告、退货、关税 | 成本项、常见比例、估算方法 |
| 物流 | 小包、专线、海外仓、带电/液体/大件 | 时效、限制、报价口径 |
| 支付 | T/T、平台收款、PingPong、PayPal | 费率、到账、风控 |
| 风险 | 选品、合规下架、封店、退货、汇率 | 触发条件、应对、止损 |

## 四、阶段层

每个档位一张“诊断卡”：

| 档位 | 判据 | 常见瓶颈 | 动作库 |
|---|---|---|---|
| 还没开始 | 预算、货源、风险承受、平台意向 | 选品、预算不足、合规不清 | 7 天验证、低成本试单、劝退条件 |
| 刚开始 | 上线时间、单量、流量、转化 | 没流量、转化低、广告亏、退货高 | 30 天对比测试、单均利润表 |
| 已经在做 | 月销、SKU、团队、广告、退货 | 利润薄、广告亏、合规、供应链 | 60/90 天利润和合规计划 |
| 公司化/多平台 | 平台数、市场数、组织、库存、数据 | 组织、库存、合规、数据 | 90 天体系优先级、资源配置 |

阶段层要回答三件事：

1. 这个档位“正常”长什么样？
2. 出现什么信号说明卡住了？
3. 先做哪一个动作，什么情况下该停？

## 五、标签与检索

每条事实卡必须带：

```text
stage       not_started / starting / operating / company / all
industry    3c / home / apparel / beauty / pet / outdoor / ...
market      us / eu / sea / jp / me / latam / all
platform    amazon / tiktok / temu / ozon / mercadolibre /独立站 / all
topic       compliance / cost / logistics / platform / risk / benchmark
source_type official / platform / public_quote / customer / estimate
source_url
updated_at
confidence  high / medium / low
```

检索顺序：

1. 按阶段、行业、市场、平台过滤。
2. 按 topic 取合规、成本、平台、风险四类。
3. 取 top 6–10 条，带来源和更新时间。
4. 找不到时，返回“待确认”，不能编造。

## 六、内容格式

用结构化事实卡，不写长报告：

```json
{
  "id": "3c-phone-stand-latam",
  "industry": "3c",
  "subcategory": "手机支架",
  "market": "latam",
  "platform": "mercadolibre",
  "topic": "cost",
  "facts": [
    {"key": "典型售价", "value": "150–250 比索", "source": "公开售价", "confidence": "medium"},
    {"key": "主要成本", "value": "头程/尾程/退货/佣金", "source": "平台公开费率", "confidence": "medium"}
  ],
  "compliance": ["按材质和功能确认"],
  "risks": ["运费占比高", "退货"],
  "updated_at": "2026-10-30"
}
```

## 七、维护

- 每张卡有来源和更新时间；过期数据标 `stale`。
- 平台规则、税率、合规每月检查一次。
- 行业事实卡先覆盖 12 个行业，每个行业 10–15 个数据点。
- 新行业先加“门槛/劝退卡”，不急着加深度报告。
- 知识库版本号与提示词版本号一起记录，方便复盘。
