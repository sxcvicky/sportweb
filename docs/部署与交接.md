# 部署与交接

> 这个文件夹是正式开发项目。`prototype/` 只作交互参考；生产代码在 `web/` 和 `server/`。

## 一、架构

```text
web/        H5 前端，静态文件
server/     单 Node 服务：API + 报告 worker + SQLite + 提示词 + 知识库
docs/       链路、提示词、知识库、部署
prototype/  原型，只作参考
```

一个服务、一个 SQLite 文件、一个部署单元。报告生成是服务内的后台任务，共用数据库和配置；不拆 Redis、不拆 worker 进程。前提是**只跑一个实例**。

## 二、本地启动

```bash
cp .env.example .env
cd server
npm install
npm run dev
```

- 前台：<http://127.0.0.1:8787>
- 后台：<http://127.0.0.1:8787/admin.html>
- 开发默认密码：`admin123`
- 默认 `LLM_MODE=mock`、`WECOM_MODE=mock`、`PAY_MODE=mock`，不需要外部密钥就能跑通全链路。

## 三、环境变量

完整变量见根目录 `.env.example`。

| 组 | 关键变量 | 说明 |
|---|---|---|
| 应用 | `APP_BASE_URL`、`APP_SECRET`、`ADMIN_PASSWORD` | `APP_SECRET` 用于签名 cookie，生产必须换 |
| 数据库 | `DATABASE_PATH` | 默认 `server/data/app.db` |
| LLM | `LLM_MODE`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` | DeepSeek 走 OpenAI 兼容接口 |
| 企微 | `WECOM_MODE`、corp/secret/回调变量、`WECOM_STAFF_USER_ID` | `mock` 时按钮模拟；`wecom` 时走活码 + 回调 |
| 支付 | `PAY_MODE`、`PAY_APP_ID`、商户号、证书、API v3 key | `mock` 时模拟付款；`wechat` 时 Native 扫码 |
| 限额 | `FREE_REPORT_DAILY_LIMIT`、`CREATE_DIAGNOSIS_HOURLY_LIMIT` | 防止刷报告 |

密钥不进 Git、不进压缩包、不进前端。生产用服务器上的 `.env`，权限设为仅部署用户可读。

## 四、Docker 部署

```bash
cp .env.example .env
# 编辑 .env：DOMAIN、APP_BASE_URL、APP_SECRET、ADMIN_PASSWORD、LLM/企微/支付
docker compose up -d --build
docker compose logs -f app
```

`.env.example` 默认是本地开发值。生产至少改这四项：`NODE_ENV=production`、`APP_BASE_URL=https://你的域名`、`APP_SECRET=强随机值`、`ADMIN_PASSWORD=强密码`。

组成：

- `app`：Node 服务，SQLite 挂载到 `./server/data`
- `caddy`：HTTPS 和反向代理，域名由 `.env` 的 `DOMAIN` 控制
- 数据目录：`./server/data`
- 备份目录：`./server/backups`

首次启动会自动执行 migration 和知识库导入。

## 五、备份

```bash
cd server
node scripts/backup.mjs
```

默认保留 14 份。生产建议每天 cron：

```cron
20 3 * * * cd /path/to/server && node scripts/backup.mjs >> /var/log/yueji-backup.log 2>&1
```

定期把备份同步到另一块磁盘或对象存储。SQLite 使用 WAL 模式，备份必须走 `.backup`，不要直接复制正在写入的 `.db`。

## 六、企微接入

两种模式：

### mock

- 提交后显示二维码占位和“我已加企微”按钮。
- 点击后把诊断标记为 `claimed`，开始生成。
- 适合开发、演示、内测。

### wecom

- 服务端调用企微“联系我”接口，按诊断生成带 `state=diag:<诊断编号>` 的活码。
- 客户扫码添加后，企微回调把 `wecom_status` 改成 `bound`。
- 前台轮询到 `bound` 后自动开始生成。
- 报告生成完成，服务端给员工发企微应用消息，员工转发报告链接。

需要确认：

1. 开通的是企微客户联系还是微信客服。
2. 回调 URL、Token、EncodingAESKey 已配置。
3. 外部联系人主动消息受 48 小时会话限制；当前 MVP 采用“员工转发 + 页面轮询”，不做客户自动推送。

回调地址：`https://你的域名/api/wecom/callback`

## 七、微信支付接入

### mock

- 不生成真实收款码，页面显示“开发环境模拟付款”。
- 点击按钮把订单标记为已付款。
- 只在开发环境使用。

### wechat

- 服务端调用微信支付 v3 Native 下单，返回 `code_url`。
- 后端用 `qrcode` 生成二维码 data URL，付款页展示。
- 微信回调 `/api/pay/wechat/notify` 验签、解密、校验金额，幂等解锁。
- 需要 `PAY_APP_ID`、`PAY_MCH_ID`、`PAY_SERIAL_NO`、商户私钥、平台公钥、`PAY_API_V3_KEY`。

回调地址：`https://你的域名/api/pay/wechat/notify`

人工标记付款只在异常兜底时使用，不替代支付回调。
